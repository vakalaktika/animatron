## Opening and editing

Run this PR's application locally (`npm ci`, `npm run dev`) and use [the opening links](open-scenes.html), or import a composition via **Compositions → Import JSON**. Raw hash links are saved beside the two vector compositions and fit the budget. The existing production application has not been deployed with Rig 2 support; use the upgraded local app. Select the rig layer, change a registered drawing under **Skeleton**, or choose a bone and pose it. Save rig and Download JSON retain the master.

Playback copies remove JSON whitespace only. `file-validation.json` records byte counts and hashes; parsed content, artwork, timing and motion are exactly equal to their separate masters. No visible simplification is claimed.

## Visual review

The bundled Detailed primary paper-airplane image and selected adult crops were viewed directly, along with Original historical references. Garden glider uses authored cheek/jaw/hair curves, descriptive eyes/noses, shaped hands and clothing, a coherent folded plane and complete interior. It composes an invented family on a window bench instead of copying the source layout. Goodnight uses simpler graphic facial marks and broad irregular room/quilt/plush silhouettes with intentional space around the sleeping child. Extra outlines, gradients and texture were not used to manufacture detail.

App-rendered frames at 0, 1, 2, 3, 4, 5, 6, 7 and 7.958 s were captured; Garden's blink/turn transitions were additionally inspected at 1.08, 1.15, 1.25 and 2.5 s. The shared hand/plane remains joined, facial marks stay with their drawings, and no frame-edge clipping or visible sleeve gap was observed. Vector and raster-part versions agree in placement; PNG edge antialiasing differs slightly from native vector rasterization. Initial PNG artwork stills used Sharp, an alternative renderer; files named `preview.frame-*` use the actual application.

Direct comparison with the request's bicycle and bedtime attachments remains unavailable because those attachments were absent from the conversation payload. These examples are finished demonstrations, not user-approved identity assets or a claim that the missing references were inspected.

## Reproduce and verify

- `node examples/illustrated-scenes/build-scenes.mjs` authors the editable curves and rigs. `build-layered.mjs` uses the application's Sharp dependency to create the explicitly separated PNG parts.
- `node --test examples/illustrated-scenes/fixtures.test.cjs`: six checks pass, covering old/shared runtime structure, positional and velocity loop continuity separately, 193-frame rigid contact, drawing holds, bird bounds, raster budgets and edit/reopen data.
- `node scripts/preview-scene.mjs <composition> <output-prefix>` mounts the app's StageCanvas in local Chrome and calls its actual `renderVideo` for MP4. Only basic stage positioning CSS is supplied by the harness; the vector/raster evaluator and export code are the application code. The fixtures use no fonts, audio or video inputs. Chrome 156.0.8078.80 was tested. `--stills-only` captures blink/turn transitions without repeating video export.
- `node scripts/qa-illustrated-scenes.mjs` after `npm run build`: built-app UI import → replacement drawing edit → raster-part bone pose → autosave → reload → Save rig/Download JSON, reduced-motion arrival and screenshots at 1440×1000 / 390×844. It uses an isolated browser profile and fake local-only data. Edited exports under `qa/` are verification fixtures, not seamless-loop masters.
